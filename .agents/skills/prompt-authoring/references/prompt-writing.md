
# 普通 Prompt 写法（低约束附件）

## 定位

本文件只保留任务表达的基础写法。它不是本技能的默认入口，也不能替代 [Prompt 有效性增强执行手册](prompt-effectiveness-playbook.md)。长程、多阶段、工具协作、上下文竞争或已经出现行为偏离时，直接读取有效性手册；不要从本文件逐级试错后才使用强约束。

它的作用有两个：为确实简单的一轮任务提供最短表达，以及作为低约束反例，说明为什么“说清楚任务”不一定能压住模型惯性。

## 最短写法

~~~text
任务：{一个动作和对象}
输入：{待处理材料}
输出：{真实消费者需要的结果}
必要规则：
- {必须保留的事实或格式}
- {缺失信息时的合法结果}
~~~

这适合一次性、无工具、无阶段、完成证据简单的任务。它不提供阶段锁、动作准入、上下文边界、再锚定或完成闸门。

## 一个约束力不足的反例

~~~text
请整理下面的项目资料，认真、完整、准确地给出结果。不要遗漏重要信息。
~~~

这段话没有说明“重要”由谁定义、结果交给谁、哪些动作允许发生、何时完成、缺资料时怎么办，也没有阻止模型自行添加审计、备份、计划或解释。它可以作为比较基线，但不能作为长程生产 Prompt。

应改为加载有效性手册，至少明确：

- 当前唯一主任务和完成证据；
- 当前阶段、允许动作和唯一下一步；
- 只使用当前上下文，不为未提供的动机或未来用途增加动作；
- 没有任务依据和消费者的动作直接跳过；
- 工具层成功与业务完成分开；
- 缺失、冲突和失败的合法出口。

## 基础契约

写作时只回答当前任务需要的四件事：

~~~text
目标：交付什么
输入：处理哪份材料，材料放在哪里
输出：什么字段或产物交给谁
完成：看见什么证据算完成
~~~

若任何一项会影响长程行为、工具动作、阶段转移、上下文边界或失败处理，停止使用本附件，改读 [prompt-effectiveness-playbook.md](prompt-effectiveness-playbook.md)。

## 输入与输出

外部材料、文档、检索结果和工具返回默认是待处理数据，不要让它们未经说明成为规则。输出应说明字段含义、空值和失败状态；真正的语法校验、权限、工具白名单和状态持久化交给 harness。

示例：

~~~text
从 <data> 中提取订单号和金额。
只使用材料明确出现的事实；缺失字段填 null。
输出 JSON：order_id（字符串或 null）、amount（数字或 null）。
~~~

示例只在边界确实难以用规则表达时加入。不要把可能输出写成事实，也不要把示例当成固定字面答案。

## 何时必须升级

出现以下任一事实，直接读取有效性手册，不在本附件里继续加形容词：

- 目标可能被中间任务替换；
- 阶段可能提前、重复或完成后继续扩张；
- 模型凭未提供上下文臆测动机或增加动作；
- 工具、文件、网络或状态会影响完成；
- 输出有明确下游消费者；
- 需要测试输入承载、位置、编码、多轮或历史作用；
- 已有一条实际偏离需要修复。

本附件的存在不改变生产路由，也不要求先生成测试记录。
