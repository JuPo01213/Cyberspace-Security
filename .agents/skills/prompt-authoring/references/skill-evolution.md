
# 技能演进、实践反馈与知识更新

## 唯一职责

本文件只处理技能本身的显式维护。它把正常使用产生的最小反馈、历史记录和外部知识快照转成下一轮技能修改的输入。它不进入普通 Prompt，不改变当前运行，不在普通触发时读取历史，也不把一条记录直接升级成规则。

正常使用：

~~~text
当前技能 + 当前任务 → run / assessment
                         ↓
                   可选最小 feedback
                         ↓
                       停止
~~~

显式维护：

~~~text
用户明确维护或达到维护条件
→ 读取反馈、历史归档和知识快照
→ 只提出一个待回答的问题
→ 修改唯一归属文件
→ 用现有行为样本回归
→ 保留、拒绝或延期
~~~

## 维护触发

只有以下情况启动维护：

- 用户明确要求审查、重构、补强或优化技能；
- 已定义的周期到达，需要检查外部知识变化；
- 同一可观察缺口反复出现，且反馈记录足以改变决策；
- 现有链接、接口或样本消费者发生变化。

普通 Prompt 调用、普通行为测试和单条反馈写入不会自动启动维护。

## 输入

维护只读取本次明确指定或维护命令指定的输入：

- 当前活动技能文件；
- 当前 run、assessment 和 feedback；
- 历史归档，例如早期记录管理材料；
- 定期获取的知识快照。

知识快照必须由上游取得，并带有来源、取得时间、内容哈希和用途。维护者把“事实、推断、建议、未知”分开；资料中的建议不是技能规则。无法追溯或无法核对的材料只能作为待调查线索，不能覆盖活动内容。

历史材料是实践反哺的证据，不是普通技能上下文。旧记录可读性差时，不把它原样塞进 Prompt；先提取当前问题需要的事实、关系和观察，再写入唯一维护记录。

## 维护问题

一次维护只回答一个能改变文件决策的问题：

~~~text
问题：哪个可观察缺口需要修复？
证据：哪条 run、assessment、feedback 或知识事实支持它？
消费者：哪个实际流程会使用这次修改？
目标文件：哪一个文件拥有该语义？
保留项：哪些原始任务、输入、输出、边界和例外不能丢？
验收：什么运行或静态检查会证明修改有效？
停止：什么证据不足时不再继续？
~~~

“整体更好”“更完整”“更专业”不是维护问题。没有唯一消费者或可失败的验收时，停止维护，不新建字段。

## 修改规则

- 先定位语义的唯一归属，再局部修改；构造原则、方法、边界和对应案例在 `input-corpus.md` 同节维护，其他文件只保留使用流程与整份手册入口，不建立逐卡跨文件回链或第二份映射。
- 原始输入和可能输出事例保留其语义；表达重组不能把可能输出伪装成观察事实。旧定性与观察说明作为明确标记的原始记录保留，不继续充当活动指导；中性机制标题不能改写原始任务含义。
- 合并文件时，把每个仍有消费者的段落放入唯一目标；无法证明去向的内容保留原样，不删除。
- 脚本只保留实际被 CLI、测试或维护流程读取的字段。
- 只有维护循环可以读取历史 feedback、历史归档和知识快照；普通命令不得读取这些路径。
- 不用哈希、快照、报告或交接字段代替实际回归。版本恢复由 Git 或真实资产匹配的恢复机制负责，维护文件不另造备份链。

## 最小反馈

反馈只记录能改变下次维护决策的事实：

~~~json
{
  "schema": "prompt-authoring/feedback-v1",
  "feedback_id": "fb-001",
  "source_run_id": "run-001",
  "source_assessment_id": "assessment-001",
  "gap": "artifact_loss | delivery_ambiguity | target_observation | assessment_mapping | consumer_gap | duplicate_process | route_contamination | coverage_gap",
  "observed_fact": "实际观察到的缺口",
  "affected_consumer": "受影响的使用者或流程",
  "proposed_owner": "唯一应修改的文件或组件",
  "evidence_refs": ["run/output.txt"],
  "status": "candidate"
}
~~~

没有 `source_run_id`、实际事实、消费者或证据引用的内容不进入 feedback。脚本不会把 `gap` 自动解释成原因，也不会自动修改技能。

## 显式维护命令

当前 `scripts/prompt-lab.py` 缺失，以下命令是待实现接口，不可直接运行；维护者直接读取当前明确指定的输入、修改活动文件并做必要验收。不得借此自动恢复旧脚本、重建环境或启动模型请求。

~~~powershell
python scripts/prompt-lab.py maintain --feedback-root <feedback目录> --knowledge-root <知识目录> --output <maintenance.json>
~~~

`maintain` 才能读取这两个输入目录，并只输出当前维护需要的文件列表、事实和待决问题。它不自动改写技能，不自动抓取网络知识，不把历史材料送给目标模型。修改仍由维护者完成，完成后用现有离线测试和必要的行为回归验收。

普通命令：

~~~powershell
python scripts/prompt-lab.py run ...
python scripts/prompt-lab.py review ...
python scripts/prompt-lab.py assess ...
python scripts/prompt-lab.py feedback ...
~~~

这些命令不读取维护输入，不创建维护提案。

## 结束标准

维护在以下任一情况停止：

- 缺口已经由一个局部修改和回归验证；
- 证据不足，下一步需要新的实际观察；
- 修改没有消费者或没有改善；
- 新知识与本地事实冲突且不能解决；
- 回归显示原有任务、输入、输出或边界退化。

停止时保留事实和决定，不继续堆规则，不把未验证推断写入活动技能。
