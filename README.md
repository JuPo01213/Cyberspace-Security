# Cyberspace-Security

这是一个面向**授权网络安全研究、样本分析、逆向工程和安全工作流沉淀**的综合仓库。

仓库同时保存研究对象、分析过程、证据材料、可复用方法、技能与历史复盘。它不是某一次任务的临时目录，也不是只存放代码的工程仓库；它更接近一个可以持续积累的授权靶场与研究工作台。

> 仅在获得明确授权的靶场、样本和隔离环境中使用本仓库内容。不得将其中的样本、脚本、方法或结论用于未授权目标、生产系统或真实攻击活动。

## 仓库内容

### 样本与靶场

`samples/` 保存授权研究用的样本和练习材料。样本文件与其解包物、运行副本、补丁、转储和日志属于不同材料；使用时应保留来源、哈希、派生关系和运行环境记录。

样本分析优先在可回滚的 Windows Guest/VM 或其他明确隔离的实验环境中进行。原始样本保持只读，任何运行时修改都只能作用于可回滚副本。

### 逆向分析与研究记录

`research/` 保存具体研究项目和专题资料，包括：

- `research/ept-sample-analysis/`：EPT 授权靶场、原始样本分析、逆向过程、动态证据和阶段复盘；
- `research/reverse-engineering/`：逆向工程工具、成熟工作流和 AI 辅助分析的研究；
- `research/windows-guest-experiment-reliability-patterns.md`：Windows Guest、持久运行、通信、收割和证据归因方面的可靠性模式。

EPT 子项目有自己的 README、`AGENTS.md`、目录规则、运行记录和证据边界。进入该子项目后，应以其项目规则为准，而不是把整个仓库的通用说明当成具体实验流程。

### Skills、Playbooks 与工作流

`skills/` 保存可复用技能的设计、参考材料和历史演进；`.agents/` 保存当前 Agent 路由所使用的技能入口（如果某项任务声明了强制 Skill，应优先读取对应入口）。

`playbooks/` 保存较完整的流程手册和历史工作流。它们用于理解设计来源、复用成熟经验和进行复盘，但不自动高于当前 `AGENTS.md`、当前项目规则或用户最新要求。

当前仓库特别强调：组件成熟不等于组合流程已经端到端验证。未经实际任务验证的工作流必须明确标注为候选方案、参考材料或未实测流程。

### 文档、历史与治理

- `docs/`：跨项目的说明、交付和协作文档；
- `history/`：规则、工作流和基础设施的历史版本与演进记录；
- `AGENTS.md`：仓库级稳定规则、脱敏要求、证据表述和能力复用边界；
- `.gitattributes`：仓库文件属性和基础版本治理配置。

## 如何使用这个仓库

推荐先阅读根目录 `AGENTS.md`，了解脱敏、证据表述、成熟能力复用和历史材料的权威级别；然后根据任务进入对应的 `research/`、`samples/` 或工作流目录。

一个具体分析任务通常应沿着以下关系组织：

`授权样本` → `隔离环境` → `静态/动态分析` → `可复核证据` → `结论` → `复盘与可复用经验`

每一次运行都应尽量使用唯一运行标识，并记录样本身份、环境、工具版本、输入输出、证据范围和清理状态。工具启动成功、通信连通、断点命中或 harness 输出本身，都不能直接写成样本业务行为已经完成。

## 证据与研究表述

仓库中的结论应区分：

- 官方文档、源码或工具直接证明的事实；
- 本项目实际运行得到的观察；
- 可以由观察推出的推导；
- 尚未验证的假设、候选解释和预测。

静态候选地址、模拟响应、宿主 harness、instrumentation canary、局部解码或单次工具成功，不能自动替代真实目标运行中的业务证据。跨运行拼接材料、把环境故障写成样本阴性、把受控放行写成自然授权，均不符合本仓库的证据要求。

## 安全边界

- 只处理已获授权的样本、靶场和实验环境；
- 不连接真实 C2、生产服务或真实授权服务；
- 不将凭据、token、私钥、个人信息、私有地址和本机绝对路径提交到仓库；
- 入库前对原始材料进行脱敏，必要时只提交可审查的文本和小型证据件；
- 原始样本、内存转储、完整网络捕获和大型二进制材料应根据项目规则隔离保存，不因方便阅读而公开；
- 不把历史材料、旧脚本或一次性实验产物自动当作当前规范。
