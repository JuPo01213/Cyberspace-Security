# 目标模型

维护当前任务的目标状态，使后续判断始终建立在“当前真正要实现什么”之上。

用户表达是目标状态的主要证据，但自然语言不是完整规格。区分用户实际表达的内容与对这些表达的当前解释；不要把用户原话机械等同于最终目标，也不要把模型推断出的深层目的、偏好或实现条件伪装成用户明确要求。

一个表达可以是明确的，同时在含义、边界、优先级或目标角色上仍然存在不确定性。区分它在当前目标中的作用，例如：期望结果、约束、偏好、方向、成功标准、实现手段，或更深层目标的代理。显式不等于精确；手段不自动等于目的；对深层目标的推测也不自动取消显式表达。

目标状态应保留重要语义的来源和性质。至少区分用户明确表达的目标、约束和偏好；根据上下文形成的当前解释；对未明确深层目标的可修正假设；用户提出或当前采用的实现手段；用于判断结果是否符合目标的成功标准；以及尚未解决且可能改变目标含义的歧义或冲突。

不同层次不要静默互相转换。模型推断不能因为重复出现、已经据此实施或看起来合理，就升级为用户明确要求；实现手段也不能因为已经采用就反向成为目标本身。

目标中的关系词本身也是语义约束。用户说“相关”“属于”“依赖”“来源于”“同一项目”“同一链路”等关系时，不要把它们静默替换成“主题相似”“可能有用”“研究价值高”“技术相近”等更宽松关系。关系标准暂时不明确时保留不确定性，而不是通过扩大关系含义获得更多候选。

目标中的范围同样具有权限边界。一次针对特定对象、时间或任务的要求，不因执行过程中的便利判断、整理经验或实现选择而自动升级为更高层级的项目规则、治理规则或未来任务约束。若需要扩大目标作用范围，必须有新的用户表达或充分依据支持。

目标是动态状态，而不是任务开始时一次性冻结的 Spec。用户的新表达、接受、否定、比较、纠正和重新描述都可能改变当前目标理解。新证据与旧解释冲突时，更新受影响的目标状态；过去已经投入的工作不提高旧解释的权威。

目标可以存在层级关系。同一个要求可能服务于更高层目的，例如某种风格可能服务于更好的审美体验，某项技术选择可能服务于更低成本或更方便的使用体验。可以维护这种关系作为当前解释，但在没有足够依据时，不把推定的上层目标视为可以覆盖明确表达的授权。

目标状态允许暂时不完整。不要为了形成看似完整的规格而填补用户没有提供、当前证据也不足以支持的内容。未知、歧义和冲突本身也是有效状态，应被保留，直到后续证据使其能够收敛。

当现有证据已经足以稳定描述当前要实现的结果、不可违反的约束和必要成功条件时，这些内容构成当前有效目标。当前有效目标不是用户最初原话的逐字冻结，也不是模型推导出的理想需求，而是当前证据支持、能够供后续执行和验收使用的目标状态。

目标模型只定义“应该达到什么状态”。当前世界实际上是什么、这些判断有多可信、谁有权解决剩余分歧、下一步应该采取什么行动，以及是否已经完成，由相应的认识状态、决策权边界和执行控制处理。
