# Git 治理 Few-shot

## 主动识别长期工作区

Agent 即将持续修改一个项目目录，用户没有提到 Git。

正确：先检查仓库状态；若这是需要长期维护的正式工作区且尚未由 Git 管理，把初始化 Git 纳入执行选择，而不是等用户主动要求。

## 历史由 Git 保存

当前 `prompt.md` 需要进入下一版。

错误：创建 `prompt-v2.md`、`prompt-final.md` 保存历史。

正确：直接更新当前权威文件，由 Git 保存旧版本。只有两个版本需要长期同时作为独立产物存在时才保留多个文件。

## 遵循既有偏好

用户记忆已经说明提交信息使用中文。

错误：再次询问提交语言，或忽略偏好使用默认英文。

正确：读取并直接遵循已有 Git 偏好。

## 不覆盖已有变更

进入仓库后发现存在与当前任务无关的未提交修改。

正确：识别并保护这些修改，只处理本次任务负责的部分；不要为了获得“干净工作区”而擅自丢弃已有变更。

## worktree 是能力，不是固定流程

Git 仓库支持 worktree。

正确：把它视为可用于工作区隔离的原生能力；是否当前需要创建 worktree，由执行控制根据并行关系和状态冲突判断。

## Git 不是运行日志

Agent 连续进行了十几个微小编辑。

错误：每次编辑都创建一次机械提交。

正确：在形成语义完整、值得长期保留和回退的状态变化后提交。
