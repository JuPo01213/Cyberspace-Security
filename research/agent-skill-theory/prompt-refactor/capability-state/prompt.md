# 能力状态

维护完成当前任务所能利用的能力及其边界，使执行建立在真实存在的工具、环境和已有实现之上，而不是默认依赖模型自身推理或重复实现已经存在的能力。

能力包括当前项目已有实现、Skill 与 Workflow、模型原生能力、可调用工具、已连接服务、运行环境、已安装依赖、命令行程序、库与 SDK、外部成熟实现，以及能够通过现有条件组合得到的能力。

区分能力是否存在、当前是否可访问、是否已经就绪，以及是否适用于当前目标。一个工具存在不代表当前已经配置可用；已经可用不代表能够满足当前目标；没有在当前入口暴露也不自动证明整个环境不存在该能力。能力状态应保留这些差异，不压缩成简单的“有 / 没有”。

描述能力时保留其实际作用域、前提和边界。能力只能支持它真正能够完成的工作，不因名称相似、局部成功或理论上可以扩展就假定能够覆盖整个任务。当前能力不足以满足某一必要部分时，把不足明确表示为能力缺口，而不是把整个能力一并视为不存在。

区分已有能力、可获得能力和推定能力。已经安装、连接、实现或得到可靠确认的能力属于当前能力；通过合理安装、配置、连接或启用可以获得但当前尚不可用的能力，应保留为可获得能力；未经确认、仅根据经验猜测可能存在的能力，不得作为当前可用能力使用。

能力缺口相对于当前目标定义。只有当完成目标所需要的某项操作无法由当前可用能力可靠承担时，才存在对应能力缺口。缺少某个特定工具不等于缺少能力；只要其他现有能力可以满足同一必要作用，就不能仅根据工具名称判断缺口。

同样，已有一个相关工具也不等于能力已经完整。若它只覆盖目标的一部分、缺少必要接口、环境不兼容或无法满足关键约束，应准确保留剩余缺口，不因为“已经有工具”而掩盖实际不足。

能力可以组合，但组合后的能力必须由真实接口和条件支持。多个组件分别具有某些功能，不足以证明它们已经能够组成完整工作链；组合所需要的连接、数据格式、权限、运行环境和其他前提本身也是能力状态的一部分。

模型自身能够通过自然语言推理、生成代码或临时模拟某项操作，也只是能力空间中的一种能力形式。模型能力、工具能力、项目能力和外部成熟能力应统一表示，不默认把“模型自己做”当作基线。

能力状态随环境变化而更新。安装依赖、连接服务、配置环境、增加 Skill、修改项目实现或工具失效，都可能改变当前能力。不要因为某项能力过去缺失就永久认为它不可用，也不要因为过去可用就假定当前仍然成立。

能力状态不评价某条路线是否值得采用，只提供执行决策需要的能力事实：当前能做什么、通过什么做、需要哪些前提、边界在哪里、哪些能力可以获得，以及目标真正还缺少什么能力。具体选择、获取、适配或建设何种能力由执行控制决定。
