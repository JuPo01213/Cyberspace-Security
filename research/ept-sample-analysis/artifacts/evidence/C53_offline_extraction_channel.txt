-- 3) what this changes for BR7 --
   Extraction moves off the live channels entirely: run the collector, power off, clone the
   session disk, mount read-only, copy the file out, then restore. Consequences that are now
   hard design requirements rather than preferences:
     * the collector must flush per line (br7.ps1 already does AppendAllText per record),
       because a hard poweroff - which is what this build needs, ACPI does not take - loses the
       unflushed tail of the file;
     * every input push must be verified by read-back BEFORE the collector starts, since the
       push window is minutes wide and CTRL3 just showed a push can silently not happen;
     * post-mortem cannot see transients: whatever the sample does and then wipes from memory
       is gone by the time the disk is read. The observable quantity is what the collector
       chose to record while the process was alive, which is exactly what the WIN/ZRIDLE
       windows are for - so the window list, not a longer wait, carries the load;
     * cost per arm: ~2 min poweroff+clone, ~80 s for 49 GB, ~10 s mount, plus a restore.
   What still cannot be closed this way: nothing new. The gate question (P4 4.16-6) needs the
   two .Sq> pages while the sample process is alive, and the collector can read them.
