## 1. 方法（事件 ID 追踪法，可复用）

## 2. 关键结构发现

1. **两套事件 ID 序列**：递减链 0xd07→0xd08→0xd09→0xd0a→0xd0b…（0x14017c41a-0x14017f963 连续状态）与递增链 0x42e1→0x42e2→0x42e4→0x42e5→0x42e7…——两个并行计数器交织（疑似：状态序号 + 会话/消息序号）
2. **加密跳转表解算成功**（方法验证）：`handler = *(0x140FA18F0) + r9*8 + 0x577a9250 + 0x51ea58a4`——表基指针值 0xE97F7B20（data_tables.bin @0x18F0）；r9=0x40 解析至 **0x14014206C**，与运行时实况自洽 ✓
3. **体接收后正常路径 handler = 0x14014731C**：事件链 `0x222f(recv 完成) → 0xf3c(本状态) → 0x7858/0x675f(cmovne 分支)`；重度布尔恒等混淆（opaque predicates）但真实逻辑可读——读 `[rbp+0x385c]` 状态字后进入分支
4. **C104 常量族（0x7FEB352D/0x846CA68B/0x01000193）在 dump 内零出现**且协议区对 0x14078xxxx helper 区零调用 ⇒ 网络协议解密独立于 pre-device 算法族（Track 2 阴性的结构性解释）

## 3. 对 E-2c Phase C 的意义

合法响应构造的剩余缺口 = 0x14014731C 起经 `cmovne edx,0x7858/0x675f` 的状态分支中，对 103 字节体缓冲（[rbp+0x30xx] 大栈帧区）的解密/校验调用链。事件图谱（§1 交付物）提供了逐状态追踪的完整索引——沿 0x7858/0x675f 分支继续反汇编即可定位解密例程与密钥来源。

## 4. 阶段反思

1. **锚点法优于线性反汇编**：403 个日志调用天然标注了状态边界——混淆填充（opaque predicates）不产生日志调用，锚点自动过滤噪声。
2. **加密跳转表可解算**：`ptr_table + index*8 + K1 + K2` 型混淆只需拿到表基指针的运行时值即可逐条目解算（两份小 dump + 模 2^64 算术）。
3. **dump 覆盖策略**：一次 `.writemem` 组合（text 512KB + 表区 80KB）支撑了本轮全部离线工作——转储清单由"反汇编时缺什么"驱动迭代扩充。

## 5. 台账
