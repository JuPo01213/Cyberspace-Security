# C107：`-n/-m` 间接分发与函数指针表边界

日期：2026-09-21  
状态：`PARTIAL / NO_PLAINTEXT_DISPATCH_EDGE`

## 目的

核对 `C15` 中出现的 `0x14078f060` 函数指针数据项，确认它们是否能把 `-n/-m` 参数解析区直接连接到本地 caller seam。该检查只使用当前 genB 的恢复 `.text` 和已有静态调用图，不启动样本、不启动虚拟机。

## 观察

- `C15_rdata_pointer_table.tsv` 在 `0x140f96304` 和 `0x140f96314` 记录了值 `0x14078f060`；相邻项还记录了 `0x14078f0ad`。
- 对 `stream_C6/stream_text.bin`（8,257,536 bytes，映射基址 `0x140000000`，SHA-256 `5ae354e2983a5bf407601b3629d114b8faa1ddd731d074e8d2092c338abdf757`）进行 x64 Capstone 指令扫描时，在 `0x140f96200..0x140f96420` 的 rdata 表范围内没有发现 RIP-relative memory operand 的引用。
- `C6_callgraph.tsv` 中存在 `0x14078f250 → 0x14078f060`，但没有以 `0x14078f250` 为 callee 的直接调用边。
- `C75` 的 `-n/-m` parser/consumer 窗口中，已确认的直接调用目标是参数复制、字符串/配置处理和 `0x14078fc90`；该窗口没有 `0x14078f250`、`0x14078f060` 或 `0x141757acd` 的直接调用边，也没有已识别的 `call [reg]`、`call qword [...]` 或 `FF 15` 形式。

## 结论

当前捕获的明文用户态代码没有提供一条可验证的“`-n/-m` parser → 函数指针表 → `0x14078f250/0x14078f060`”静态边。已有指针表项可能属于未恢复的运行时分发数据，也可能只是同一 rdata 区中的其他表数据；仅凭其数值不能把自然命令行路径连接到 caller seam。

因此，C107 不改变 C100 的边界结论：C90/C105 的 caller 参数仍是 synthetic，不能冒充自然 `-n/-m` 输入。继续闭合这条路径需要运行时表初始化/调用观测或更完整的保护代码，不应通过补写一个假 caller、重复扫描当前明文 `.text` 或延长 VM 等待来填补。

## 限制

该扫描只排除了当前恢复 `.text` 中的直接 RIP-relative 引用和已提取的 direct-call 边；它不能排除运行时生成的绝对地址、寄存器间接调用、未捕获模块或 VMProtect 解密后的新代码。因此状态保持为未决，而不是“自然路径不存在”。
