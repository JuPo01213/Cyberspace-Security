# C69：核心网络进度边界（2026-09-21）

## 结论

**已有抓包证明核心启动会话中发生了 `yz.hwid001.com` 的 DNS 解析，但没有证明授权请求真正建立或返回。** 这比“只看到进程启动”更进一步，但仍不足以证明业务解码成功。

## 证据强度与限制

- DNS 查询/应答是会话级观察，不能单独证明发起者 PID 是 `Hardware.exe`；但它与“核心启动”会话相关，并且在无样本的 IDLE 对照和 hosts 钉死对照中消失，支持“与样本链路相关”的解释。
- 由于没有到 fake-IP 的后续连接，当前不能说已经发出授权报文、收到服务端返回码或进入 8 码放行/阻断表。
- 抓包只能回答网络是否出现，不能回答核心内部是否在本地完成了其他授权前置计算。

## 合并结论

当前动态链条可以写成：

> 外层真实启动核心 → 核心启动后所在会话解析 `yz.hwid001.com` → 没有观察到到解析地址的授权连接 → 没有授权返回码、弹窗结果或业务完成标志。

因此“业务解码实际发生了吗”的答案仍是：**核心进入了授权网络前置阶段，但业务解码是否成功发生仍未知；现有网络证据更接近“解析后未建立授权连接”，而不是“已完成解码”。**
