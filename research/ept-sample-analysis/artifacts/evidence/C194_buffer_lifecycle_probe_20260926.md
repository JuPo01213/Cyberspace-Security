# C194 · recv 缓冲区生命周期探测与下一阶段设计

日期：2026-09-26 · 运行：EPT-AUTHGATE-20260925-80（快线变体，RECV×2+FATAL×1，探针 echo）

## 1. 本轮实验

设计：recv#2 断点动作内保存 rdx（响应缓冲区）至 `$t10` 并即时转储（`recvbuf_at_recv.bin`）；FATAL_THUNK 动作内再次转储同一缓冲（`recvbuf_at_fatal.bin`）对照。

结果：
- `recvbuf_at_recv.bin` = 103 字节**全零**（recv 入口断点=数据到达前，符合预期）
- FATAL 时刻 `db @$t10 L67` → **`Unable to read memory at 0x001f0004`**——缓冲区为**堆分配且已释放**（堆地址 0x1f0004，状态机处理完成后被 free）

## 2. 结论与推断

1. 103B 帧体的处理完全在**堆缓冲区生命周期内**完成（recv 返回 → 状态机解密/校验 → free），FATAL 时明文/中间态已不可从该地址获取。
2. 解密例程位于状态机链条 0x14014731C →（cmovne 索引 0x7858/0x675f）→ 0x14019349d → 0x1400f77ae → … 的更深处；该链为控制流平坦化+全局间接引用（`[rax-0x2ff86eb0]` 型），静态逐跳追踪成本高。
3. 事件图谱方法（C193）仍然有效：状态链条由事件 ID 序列标注，解密状态的定位 = 沿锚点链找到第一个"读 103B 缓冲 + 输出变换"的状态。

## 3. 下一阶段实验设计（按成本排序）

1. **堆缓冲区时序快照**：在 recv#2 动作内对缓冲区地址设置页保护（VirtualAllocEx 不可用；改用 `ba e` 不行——DR 槽满）→ 改为：在状态链条的已知锚点（0x14014731C 后续状态的日志调用点）动作内反复 `.writemem` 缓冲快照（@$t10 有效期内），时间序列对比定位解密发生的状态。
2. **WSARecv/recv 返回值追踪**：`bu ws2_32!recv` 动作内的 `gu` 捕获返回后缓冲内容（echo 场景=我们的回声），确认 recv 成功后再沿状态链找变换。
3. **扩展 dump 至堆**：recv#2 时记录缓冲地址，FATAL 前在任意后续锚点断点（如 WriteFile/日志器调用）动作内 `.writemem` 整个堆段（堆地址经 `!heap`/VirtualQuery 定位）。
4. **变体探针矩阵**：响应长度/内容变体（len=0/len=107 零体/随机）触发不同状态路径——状态机的失败分支差异本身泄露校验逻辑（echo 已证明此法有效）。

## 4. 阶段反思

1. **缓冲区生命周期意识**：I/O 缓冲是堆分配、处理完即释放——"事后转储"必须换成"生命周期内多点快照"。断点动作内保存指针到伪寄存器（$t10）跨断点传递是可行模式（本次验证）。
2. **堆地址 0x1f0004 极低**：子进程堆段布局紧凑——Full dump 一次覆盖（进程全堆 dump 一次 ≈ 数十 MB，成本可控），下轮可直接全堆转储替代逐点快照。
3. **控制流平坦化的静态追踪成本**远高于运行时观测——静态只用于"已定位的例程"，动态负责"定位"本身。
